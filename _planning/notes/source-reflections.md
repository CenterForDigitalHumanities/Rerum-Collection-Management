## Best ideas extracted

1. RERUM should not be merely storage; it is the persistence layer for scholarly graph events.
2. Mirador-like tools should be clients over shared annotations, not special cases.
3. Dynamic collections are best understood as annotations that can be assembled into views.
4. Remote objects should not need to be copied or modified; local improvements belong in annotations and version-aware RERUM objects.
5. Identity can begin as a URI anchor with evidence, not as a complete catalog description.
6. Description should happen through attributable assertions.
7. DEER-like rendering suggests that assembled views can be generated from base objects plus targeting annotations.
8. The ecosystem should be technologically plural: viewers, connectors, data entry tools, static exhibitions, inbox announcements, and graph explorers can all share a common JSON-LD substrate.
